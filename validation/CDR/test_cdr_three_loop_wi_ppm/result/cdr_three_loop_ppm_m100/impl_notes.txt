2026-09-25 追加: 根因定位为换挡判据缺陷, -100 ppm 全相位捕获已实现 (32/32)

本节更正上文"待定 / 物理根因是采集方向不对称"的结论。上文列出的参数穷举之所以
全部失败, 是因为一直在与一个判据缺陷搏斗, 而不是参数没调够。

--------------------------------------------------------------------------------
一、根因 (已因果验证)
--------------------------------------------------------------------------------
src/CDR/loop_monitor.m:217 的 dLev 换挡判据是一个两点位移测试:
    abs(dlevOuter - dlevOuter_{blockIndex-DlevSettleWindow}) <= DlevSettleTol
它等价于一个隐式漂移速率门限 DlevSettleTol/DlevSettleWindow = 0.5/16
= 0.031 code/block。实测冷启动 dLev outer 的漂移率只有约 0.012 code/block, 轻松
满足该门限 => 在 block 84 误判为"已收敛", 此时 outer = 41.36 而终值为 31.99,
即整条轨迹还剩 59% 未走完, 眼远未张开。

该误判在 src/CDR/cdr_top.m:453-455 同时触发两件事:
    dLev 步长 0.5   -> 0.1     (5x)
    FFE  步长 0.004 -> 0.0002  (20x)
唯一能把眼撑开的 FFE 恰在此刻被降速 20 倍 => 眼长期闭合 => 判决导向 PD 偏置长期
为负 => 积分器单调绕到 FrequencyLimit=-4 钳位 => 全部起始相位失败。

隔离实验 (-100 ppm, 8 起始相位, 其余默认):
    默认(两档都降)                 : 0/8
    只保住 FFE 捕获步长            : 8/8   <= 致命项
    只保住 dLev 捕获步长           : 0/8
故致命的是 FFE 的 20x 降档; dLev 的 5x 降档无害。

上文观察到的"± 方向不对称"本身是真实的, 但它是放大机制而非根因: 冷启动闭眼下的
天然 PD 偏置为负(约 -0.016), 而 -100 ppm 需要频率态收敛到 +0.8192(正), 偏置与所
需方向相反故被推向钳位; +100 ppm 需要 -0.8192, 偏置同向故"侥幸"成功。一旦 FFE
不再被提前降速, 两个方向都能正常捕获。

--------------------------------------------------------------------------------
二、修复: 两级降档 + 眼质量门控
--------------------------------------------------------------------------------
第一级 (capture -> settle), 门控换成眼质量, 两个环路同时降:
  FOM = 判决导向 SNR = 10*log10(mean(decision^2)/mean(sliceError^2)), 逐 block。
  cdr_top 已有现成材料 (decision/sliceError 在 slicePam4 处算出), 新增静态方法
  cdr_top.blockSnrDb; 判决逻辑放在 loop_monitor.updateSnrSettle (只判决不施加,
  沿用该类既有契约), 由 enableSnrSettle(thresholdDb, alpha, minBlock) 显式开启,
  构造函数 4/6 参数契约不变。
  平滑是必要组成而非修饰: 逐块 SNR 分布严重重叠 —— 失败运行(闭眼)的 p99 = 22.55 dB
  甚至高于成功运行尾窗的最小值 17.50 dB, 因为积分绕到钳位后 PI 持续旋转, 采样点
  周期性扫过眼心会给出漂亮的单块读数。取 EWMA 后两者才分开:
      alpha=1/32  : 失败运行 EWMA 峰值 14.59..14.73 dB
      alpha=1/128 : 失败运行 EWMA 峰值 13.02..13.12 dB (采用)
      成功运行     : 21.6..24.4 dB
  阈值实测下限: 11 dB 会打断 -100 ppm (0/8); >=12 dB 可行。取 15 dB, 距闭眼峰值
  约 1.9 dB, 距眼开稳态约 6.6 dB。minBlock=200 压住均值预热期。

第二级 (settle -> PVT tracking), 沿用既有相位带锁定门控 loop_monitor.updateFfeGate
(FfeGate* 参数不变), 触发后两个环路再各降一档:
      FFE  -> FfeStepSizePvtTrack  = 2e-4
      dLev -> DlevStepSizePvtTrack = 0.02   (新增配置)

--------------------------------------------------------------------------------
三、capture 期 FFE 步长必须调小: 游标走位
--------------------------------------------------------------------------------
FfeAdaptEnableMask = [1 1 0 1 1 1] 冻结主抽头, 环路只能靠前后抽头整形脉冲, 这会
移动有效游标位置, 从而移动 MMPD 的零点 => 不同起始相位收敛到不同的锁定相位。
走位量与 capture 步长成正比, 实测锁定相位离散度(8 起始相位, 单位: code):
    FfeStepSize   0.001  0.002  0.004  0.008
    0 ppm 离散度      3      6     12     21
    +100 ppm 离散度   1      2      5     13
0.004(库默认)下 0 ppm 离散度 12 码超出 captureBandHalfWidth=6 判据。故本套件
default FfeStepSize 定为 0.001 —— 在三个 ppm 都留在捕获带内的前提下取最大值。
注意这是"越小越一致"与"越小开眼越慢"的取舍, 0.001 已同时满足两端。

七、三眼窗口、结果、限制与复现
--------------------------------------------------------------------------------
make_ppm_stage_eyes.m 先从保存的 SnrDbTrace 精确重放
loop_monitor.updateSnrSettle 的 EWMA，再用与运行 pass/fail 完全相同的锁定检测器和容差
逐个前缀 1:k 重放首次锁定。三个 2048-UI 窗口依次为：
  1) 第一级 SNR mu 降档后：从 block 3864 开始；这是 block>=200 后 EWMA(alpha=1/128)
     首次达到 15 dB 的位置。
  2) 锁定判据首次满足后：从 block 6128 开始；本工况按
     loop_monitor.detectFrequencyStateLock，并在 RotationCriterionApplicable 时同时要求
     detectRotationPeriodLock。频率态单项判据也在 block 6128 首次满足。
  3) final：运行最后 2048 UI。
LockWindowBlocks=2000，忠实的滑窗判定在 block 2000 前没有完整窗口，因此第二行锚点
下限为 2000；它表示“末尾 2000-block 窗口首次满足判据的块”，不是环路锁定的瞬时刻。
CaptureBlock=3787 只保留作上下文，不再作为眼图锚点。

helpers/build_ppm_eye_set.m 接受 N 个锚点并追加一个尾窗，按
    absSample0(k) = (BaseUi + (k-1)*AdcBlockUi + UiSlipTrace(k)) * ...
        SamplesPerUi + PhaseCodeTrace(k) + DriftSampleTrace(k)
重建频偏地址，并逐块精确核对其 sub-UI code 与 EyePhaseUnwrappedTrace。每个锚点窗口
使用该锚点块自己的 FFE 系数快照，final 使用末块快照；它们都是整窗固定抽头的离线视图，
不是运行期逐块变化抽头的重放。ADC、固定抽头 FFE 和 2-UI 密度仍委托同级
build_cdr_ffe_eye。helpers/plot_ppm_eye_set.m 输出三个独立图，并另画一个刻意设为
1500x1500 的三行比较图。marker 由未包裹的 tracked-eye phase 先统计、再包裹到一 UI；
span 因而可跨越 0/128 边界。相邻 2-UI 密度列彼此重叠，不能视为独立样本。

--------------------------------------------------------------------------------
九、本次改动: 采样地址改走 PI 相位表, 默认非理想 PI
--------------------------------------------------------------------------------
1. runner 新增 PiNonideal 选项('ideal'|'ab_constant'), 默认 'ab_constant', 并传给
   cdr_top; 此前 runner 把 cfg.PiNonideal 硬写成 'ideal'。cdr_pi 的 a+b=1/atan2
   相位表模型与 cdr_top 的 PiNonideal 校验都是既有代码, 本次未改。
2. 只加选项是不够的: 原来块起始地址用的是原始 CodeWrapped, 它隐含"code 到相位完全
   线性"的假设, 于是 cdr_pi 算出的非理想相位表会被算完即丢。现在在 UI 内的采样偏移
   取自相位表本身:
       sampleOffset = round(top.PhaseInterpolator.getLocalIndex())
   在 PiNonideal='ideal' 下该表恰为恒等表, 所以此式等于 CodeWrapped, 改动是逐比特
   no-op —— 保留 'ideal' 正是为了让旧行为仍可复现、可做 A/B。
3. 定量(PiNumBit=7, 128 sample/UI, 1 LSB = 1 code = 1 个波形样点):
   ab_constant 相位表 INL = ±1.445352 LSB, 即 2.890703 LSB pk-pk, RMS 1.037876 LSB。
   缓存按整数样点寻址, 故偏移被 round, INL 被量化到 ±0.5 LSB。实际存活的扰动是
   round(localIndex)-code ∈ {-1, 0, +1}, 分别覆盖 52/24/52 个 code, 也就是
   **128 个 code 里有 104 个的采样点相对旧的理想 PI 地址移动了整整一个样点(1/128 UI)**。
   同一个 round 会把 0.7 LSB pk-pk 以下的 INL 完全抹平: 这是本 harness 整数寻址的
   限制, 不是 cdr_pi 的限制; 想研究更细的 INL 必须对缓存做分数插值, 本次没做。
4. 已否决(用户确认): 不做 PiInlPkPkLsb 幅度缩放旋钮。原生 2.891 LSB pk-pk 就是物理
   模型本身, 合成缩放因子只会诱使报告一个整数寻址其实表示不出来的 INL 水平。
5. 五张收敛图(相位/dLev/FFE 抽头/环路频率态/PI 跟踪误差)新增两级降档标记:
   stage-1 绿色(带 SNR 阈值), stage-2 紫色, 两者都 NaN-safe(没发生就不画)。stage-2
   标签写的是**所armed的门控名**(gate: freq-state|center-touch), 不写成 "lock":
   只有 freq-state 门才是锁定判据的一个分量, center-touch 是独立的码域判据。
6. 新增 result 字段: PiNonideal / FfeGateCriterion / Stage1SettleBlock /
   Stage2GateBlock / AdcBlockUi / CdrFfePreTapCount。前两个 block 字段取自 monitor
   自己的闩锁, 不是离线反推, 所以不可能和当次真正armed的判据不一致。

--------------------------------------------------------------------------------
十二、限制与遗留
--------------------------------------------------------------------------------
- INL 被整数寻址量化成 {-1,0,+1} 三级台阶, 亚 LSB INL 在本 harness 中无法表示。
- 本次未在非理想 PI 下重新探负方向的 ppm 边界(只确认 -100 ppm 达标)。
- 上文第七节写的 "本目录 Stage2Block 全为 n/a" 只适用于旧产物; 本次为 32/32 触发。
- ppm_lock_summary.txt 原先称 freq-state 的 Stage2Block 与 LockBlock "by
  construction" 相等, 这个说法过强: 非零 ppm 的判据是合取, 还要求
  detectRotationPeriodLock, 因此正确的结构性结论只能是 Stage2Block <= LockBlock。
  该文件现已改为这样表述, 并打印实测一致性(本工况 32/32 行精确相等, 0 行更早)。

十三、复现方法
--------------------------------------------------------------------------------
从套件目录:
    setup_cdr_three_loop_wi_ppm_paths('all');
    r = cdr_three_loop_ppm('FreqOffsetPpm', -100, 'StartPhaseStep', 4);
    make_ppm_stage_eyes('ResultDirs', {'cdr_three_loop_ppm_m100'});
第一条即本节结果(其余全默认: NumBlock=15000, PiNonideal='ab_constant',
FfeGateCriterion='auto'); 第二条离线重建三眼并刷新 ppm_lock_summary.txt。
恢复旧的理想 PI 行为(逐比特等价于本次改动之前):
    cdr_three_loop_ppm('FreqOffsetPpm', -100, 'StartPhaseStep', 4, ...
        'PiNonideal', 'ideal');
快速 smoke:
    cdr_three_loop_ppm('FreqOffsetPpm', -100, 'NumBlock', 4000, ...
        'StartPhaseList', [0 64], 'SaveOutputs', false);
注意 StartPhaseStep 默认是 16(只有 8 个相位), 本套件历史上的"全相位"指 32 相位,
必须显式传 4。重跑同一条命令可复现相同的汇总数值(确定性)。
