--------------------------------------------------------------------------------
一、测量目标与判据
--------------------------------------------------------------------------------
在"当前配置"(即 runner 全默认: PiNonideal='ab_constant' 非理想 PI,
NumBlock=15000, FfeGateCriterion='auto', Kp=8, Ki=0.03, MaxDeltaCode=1,
FrequencyLimit=4, planB 冷启动, 缓存 channel_ctle_cosim_prbs22)下, 测量能实现
"全起始相位锁定"的最大频偏范围。

通过判据(三条同时成立):
  1) 每个起始相位都 locked;
  2) AllPhaseLock == 1 (各相位存在公共锁定相位);
  3) 无相位被判 slew 饱和。
三项分别报告, 避免把部分失败折叠成一个布尔值。

**必须注意的判据耦合(本次测量的核心发现之一)**:
runner:482-490 为
    lockedFlag = freqLockFlag && rotationLockFlag && ~slewSaturatedFlag
即 slew 饱和守卫本身就是锁定判据里的一个否决项。因此 "locked 数量下降" 与
"sat 数量上升" **不是两个独立证据**, 前者部分是后者造成的。这直接导致下面必须区分
两个完全不同的边界。

--------------------------------------------------------------------------------
二、方法
--------------------------------------------------------------------------------
1. 8 相位阶梯(StartPhaseStep=16)粗定位 + 整数二分, 定出边界对。
2. 对通过的候选点做 32 相位(StartPhaseStep=4)确认。
   只需确认"通过"点: 8 相位表 0:16:112 是 32 相位表 0:4:127 的**真子集**, 且每个起始
   相位是独立确定性运行, 所以 8 相位失败必然蕴含 32 相位失败, 无需重跑。
3. 放松 slew 守卫再测一遍(SlewSatPendingTol=1e9, SlewSatDeltaFrac=1;
   validateattributes 要求 finite 故不能传 Inf), 把"守卫定义的边界"与"频率跟踪本身
   的边界"分开。
4. 同时用 PiNonideal='ideal' 做对照, 量化非理想 PI 的代价。
二分法假设判据对 |ppm| 单调; 所有阶梯点均记录在下表, 该假设可自行核对, 且边界对
(B 通过 / B±1 失败)总是显式跑过。

四、结果 B: 放松守卫后, 频率跟踪本身能到多少(关键区分)
--------------------------------------------------------------------------------
SlewSatPendingTol=1e9, SlewSatDeltaFrac=1, 其余默认, 非理想 PI, 8 相位:

   ppm  freqL  rotL  locked  all  sat   maxPend  maxDelta    freqErr
  +103    8/8   8/8     8/8    1    0    0.6070    0.8445   2.03e-04
  +105    8/8   8/8     8/8    1    0    0.6325    0.8615   9.55e-05
  +110    8/8   8/8     8/8    1    0    1.0240    0.9015   2.39e-04
  +115    8/8   8/8     8/8    1    0    1.7195    0.9435   2.78e-04
  +120    7/8   8/8     7/8    0    0   12.7570    0.9840   1.53e-02
  -106    8/8   8/8     8/8    1    0    0.5110    0.8690   1.12e-04
  -110    8/8   8/8     8/8    1    0    0.7270    0.9020   3.04e-04
  -115    8/8   8/8     8/8    1    0    1.3405    0.9430   3.89e-04
  -120    8/8   8/8     8/8    1    0    6.7635    0.9840   5.44e-03

==> 结论: **+102/-105 这个边界是"守卫阈值定义的", 不是频率跟踪失效点。**
    把守卫放松后, 频率态判据与旋转周期判据在 +115 / -120 ppm 仍然 8/8 满足,
    频率态误差仍在 4e-4 以内。跟踪真正开始崩的地方是 ±120 ppm 附近
    (+120: 7/8, AllPhaseLock=0, freqErr 1.5e-2; -120: 仍 8/8 但 freqErr 5.4e-3)。

为什么放松守卫后仍能跟住: 只要积压是**有界**的, 稳态下实际施加的平均速率必然等于
需求速率(否则积压会无限增长)。maxDelta 列证实了这点: 它在每个点都等于理论需求速率
(ppm/122.07), 一路到 +120 的 0.9840。代价是相位有一个静态滞后, 约 maxPend 个 code,
例如 +110 的 1.02 code = 1.02/128 UI ~= 8 mUI。所以 SlewSatPendingTol=0.5
(~3.9 mUI 滞后) 是一个**设计判断**(可接受多少 slew 滞后), 不是物理失锁点。

积压随利用率的爆炸式增长是排队论特征: util 0.8445->0.9015->0.9435->0.9840 时
maxPend 0.607->1.024->1.720->12.757, 与 1/(1-util) 同趋势(util=0.984 时约 62 倍)。
这也解释了为什么 ±120 ppm 之后无法再谈"跟踪"。

--------------------------------------------------------------------------------
五、结果 C: 算术硬上限与非理想 PI 的代价
--------------------------------------------------------------------------------
硬上限(纯算术, 任何调参都不能突破):
    PI 每 block 最多走 MaxDeltaCode=1 个 code, 1 code = 1/128 UI, 1 block = 64 UI
    => 最大相位速率 = 1/(128*64) = 1/8192 UI per UI
    => ppm_max = 1e6/8192 = **122.07 ppm**
    100 ppm 需要 0.8192 code/block, 即占用 81.92% (result.SlewUtilization)。
故 "±1 code/更新 => 最大约 100 ppm" 的准确说法是: 硬上限 122 ppm, 而 ±100 ppm 是能
塞进去且留有余量的规格点。上表 maxDelta 全部等于 ppm/122.07, 直接印证该模型。

理想 PI 对照(PiNonideal='ideal', 默认守卫, 8 相位):
   ppm  locked  all  sat   maxPend   verdict
  +110    8/8     1    0    0.4530   PASS
  +115    0/8     0    8    0.9680   FAIL
  +120    0/8     0    8    5.6390   FAIL
  -110    8/8     1    0    0.3290   PASS
  -115    0/8     0    8    0.7645   FAIL
  -120    0/8     0    8    4.0450   FAIL

==> 理想 PI 在默认守卫下是**对称**的 ±110 通过 / ±115 失败;
    非理想 PI 收缩为 +102 / -105, 即 INL 在正向吃掉约 8 ppm, 负向约 5 ppm, 且**不
    对称**。同 |ppm| 下非理想的积压更大(+110: 1.024 vs 理想 0.453), 这与 ±1 样点的
    INL 地址量化需要额外 code 运动一致; 但"为何正向比负向更贵"未做受控归因, 仅记录
    现象(两个方向的锁定相位分别落在 121 与 106/107, 处于 INL 曲线的不同区段)。

--------------------------------------------------------------------------------
六、限制
--------------------------------------------------------------------------------
- 静态 Channel+CTLE 缓存 + PRBS22, 不含噪声/抖动/PVT; 未测 BER 与抖动容限。
  因此这里的"可跟踪范围"只针对确定性频偏跟踪, 不是抖动容限指标。
- 结果 B/C 的多数点为 8 相位探测, 仅 +102/-105 做了 32 相位确认。8 相位通过不保证
  32 相位通过(反向蕴含才成立), 故结果 B 的 ±115/±120 结论仅为 8 相位量级结论。
- 二分假设判据随 |ppm| 单调; 所测各点未出现违背, 但未穷举每个整数 ppm。
- -107 ppm 出现部分相位彻底发散(maxPend 9259, freqErr 3.72)而 -106/-110 为"干净"
  失败, 失效严重程度非单调; 只有 pass/fail 判决在所测点上是单调的。

--------------------------------------------------------------------------------
七、复现方法
--------------------------------------------------------------------------------
从套件目录:
    setup_cdr_three_loop_wi_ppm_paths('all');
    ppm_tracking_range();                       % 默认: 边界对 8 相位快速校验
    ppm_tracking_range('PpmList', [100 102 103 105 110], 'StartPhaseStep', 16);
    ppm_tracking_range('PpmList', [102 -105], 'StartPhaseStep', 4);   % 32 相位确认
    ppm_tracking_range('PpmList', [103 110 115 120], 'RelaxSlewGuard', true);
    ppm_tracking_range('PpmList', [110 115 120], 'PiNonideal', 'ideal');
所有调用都 SaveOutputs=false, 不会覆盖 result 目录。runner 是确定性的, 同一条命令
可复现上表数值。
