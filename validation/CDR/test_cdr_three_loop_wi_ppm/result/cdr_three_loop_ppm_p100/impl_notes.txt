--------------------------------------------------------------------------------
一、验证目标与整体结构
--------------------------------------------------------------------------------
在标准以太网要求的 +/-100 ppm 采样时钟频偏下，验证 CDR 三个并发环路
(SS-MMPD 相位环 / dLev 电平环 / CDR-FFE SS-LMS) 能否实现"全初始相位捕获"。
脚本派生自 cdr_dlev_cdrffe_sslms_v4，被测 DSP 核仍为 cdr_top(config)，本脚本
只负责缓存读取、TI ADC 采样、频偏注入、起始相位扫描、trace 收集、判据与绘图。

--------------------------------------------------------------------------------
二、关键实现要点与设计取舍
--------------------------------------------------------------------------------
1. 频偏注入 = 方案 A (RX 时钟模型)，波形缓存不重采样：
   - 一个数据符号在缓存网格上恒占 128 个样本；频偏体现在 RX 采样步长：
     每个 RX UI 读指针前进 128*(1+delta) 个样本, delta = FreqOffsetPpm*1e-6。
   - 128*(1+delta) 非整数，故维护浮点累积漂移，只在取 block 起始地址时对
     "累积值"取整一次: driftSample = round(driftRatePerBlockCode*(blockIndex-1))，
     加到 blockStart。对累积值取整(不对增量)使量化误差恒 <= 0.5 sample = 1/128 UI，
     与 PI 分辨率同阶。块内 64 个采样仍按 128 等间隔(块内漂移 <=0.82 sample 不建模)。
   - driftRatePerBlockCode = ppm*1e-6*128*64。100 ppm => 0.8192 code/block，
     PI 旋转周期 = 128/0.8192 = 156.25 block/UI。cdr_top 完全不知情(激励/被测边界干净)。

2. 锁定判据可切换(保留 0 ppm 判据，不删除):
   - FreqOffsetPpm==0: 沿用 v4 的众数 center-touch (detect_pi_center_touch_lock)。
   - FreqOffsetPpm~=0: src/CDR/loop_monitor.m 新增两个静态判据，二者都成立才算锁:
       (a) detectFrequencyStateLock: 环路积分器频率态尾窗均值恒定(前后半均值一致、
           std 小)且量级匹配期望漂移率。量级匹配对符号不敏感(避免 PD/采样极性约定影响)。
       (b) detectRotationPeriodLock: PI 旋转周期(相邻 UI-slip 间隔)恒定(CoV 小)=已跟踪，
           不恒定=仍在采集。
   - 需求诊断(不入判据): result.PiTrackingErrorTrace / cdr_pi_tracking_error.fig =
     PI 实际码减去理想偏移补偿码(= unwrapped+driftSample-C)，跟踪后为平线，采集中为斜坡。

3. 频率采集的先决条件(重要结论): 采集期"眼必须是开的"。冷启动 planB([0 0 1 0 0 0])下
   眼在前若干 block 是闭的，而频偏已在漂移，从远端起始相位环路会把积分器锁到错误的
   S 曲线斜率并冲到频率钳位。本 +100 ppm 结果用的是冷启动 planB 且默认参数即可全相位锁定，
   因为 +100 ppm 所需的补偿方向恰好与冷启动初始瞬态偏置一致(见四)。-100 ppm 不成立，
   详见 result/cdr_three_loop_ppm_m100/impl_notes.txt。

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
四、关键结果与结论 (+100 ppm)
--------------------------------------------------------------------------------
- 8/8 起始相位全部锁定, AllPhaseLock=1 (ppm 一致性带宽 16 code = 1/8 UI)。
- 频率态尾窗均值 FreqStateMean 全部 = -0.8191 (理论期望 -0.8192, 误差 <1e-4 code/block)。
- 旋转周期 156.17..156.42 block/UI (理论 156.25), 周期 CoV 0.004..0.010 (跟踪极稳)。
- 眼相位码 114/124/126/127/0/117/116/115 (circular 都落在 ~120±7 一致弧, spread=14 code)。
- 采集(首捕)块 77..589, 快速捕获。dLev 收敛正常。
- 结论: +100 ppm 冷启动 planB 默认参数即可实现全初始相位频率捕获与跟踪，
  两个频域判据(频率态均值恒定 + 旋转周期恒定)一致判定锁定。

2026-09-25 追加: 两级降档 + 眼质量门控后重跑 (32 起始相位, 离散度 14 -> 2 码)
================================================================================
为修复 -100 ppm 全相位捕获失败, 换挡策略与 capture 期 FFE 步长已改动。根因分析与
判据设计的完整记录见 result/cdr_three_loop_ppm_m100/impl_notes.txt 的同日小节;
本节只记录 +100 ppm 侧的影响与新结果。

改动摘要:
- 第一级降档(capture->settle)门控由 dLev 位移判据改为判决导向 SNR 的 EWMA 判据
  (SettleGate='snr', 阈值 15 dB, alpha=1/128, minBlock=200), dLev 与 FFE 同时降。
  旧判据是隐式速率门限 0.5/16=0.031 code/block, 冷启动 dLev 漂移率仅 0.012, 会在
  block 84 误判收敛并把 FFE 步长砍 20 倍。
- 第二级降档(settle->PVT)沿用既有相位带锁定门控, 新增 dLev 侧 DlevStepSizePvtTrack
  = 0.02 (原先只降 FFE)。
- capture 期 FfeStepSize 0.004 -> 0.001: 主抽头被冻结时环路只能靠前后抽头整形,
  会移动有效游标从而移动 MMPD 零点, 走位量与步长成正比。+100 ppm 侧实测锁定相位
  离散度随步长 0.001/0.002/0.004/0.008 = 1/2/5/13 码。

新结果 (32 起始相位 0:4:127, NumBlock=8000, 纯默认参数):
- 32/32 起始相位锁定, AllPhaseLock=1, 频率判据 32/32。
- freqStateMean -0.8192..-0.8191 (理论期望 -0.8192)。
- commonLockPhase=120, 锁定相位离散度 2 码 (上文 8 相位旧配置为 14 码)。
- 对照同配置下 -100 ppm 与 0 ppm 亦为 32/32 AllPhaseLock=1 (离散度 3 / 3 码)。

即上文"+100 ppm 默认参数即可全相位捕获"的结论仍然成立, 且锁定相位一致性显著改善;
同时 -100 ppm 不再是待定项。复现方式不变(默认参数)。

六、三眼窗口、结果、限制与复现
--------------------------------------------------------------------------------
make_ppm_stage_eyes.m 先从保存的 SnrDbTrace 精确重放
loop_monitor.updateSnrSettle 的 EWMA，再用与运行 pass/fail 完全相同的锁定检测器和容差
逐个前缀 1:k 重放首次锁定。三个 2048-UI 窗口依次为：
  1) 第一级 SNR mu 降档后：从 block 526 开始；这是 block>=200 后 EWMA(alpha=1/128)
     首次达到 15 dB 的位置。
  2) 锁定判据首次满足后：从 block 2593 开始；本工况按
     loop_monitor.detectFrequencyStateLock，并在 RotationCriterionApplicable 时同时要求
     detectRotationPeriodLock。频率态单项判据也在 block 2593 首次满足。
  3) final：运行最后 2048 UI。
LockWindowBlocks=2000，忠实的滑窗判定在 block 2000 前没有完整窗口，因此第二行锚点
下限为 2000；它表示“末尾 2000-block 窗口首次满足判据的块”，不是环路锁定的瞬时刻。
CaptureBlock=511 只保留作上下文，不再作为眼图锚点。

helpers/build_ppm_eye_set.m 接受 N 个锚点并追加一个尾窗，按
    absSample0(k) = (BaseUi + (k-1)*AdcBlockUi + UiSlipTrace(k)) * ...
        SamplesPerUi + PhaseCodeTrace(k) + DriftSampleTrace(k)
重建频偏地址，并逐块精确核对其 sub-UI code 与 EyePhaseUnwrappedTrace。每个锚点窗口
使用该锚点块自己的 FFE 系数快照，final 使用末块快照；它们都是整窗固定抽头的离线视图，
不是运行期逐块变化抽头的重放。ADC、固定抽头 FFE 和 2-UI 密度仍委托同级
build_cdr_ffe_eye。helpers/plot_ppm_eye_set.m 输出三个独立图，并另画一个刻意设为
1500x1500 的三行比较图。marker 由未包裹的 tracked-eye phase 先统计、再包裹到一 UI；
span 因而可跨越 0/128 边界。相邻 2-UI 密度列彼此重叠，不能视为独立样本。

八、本次改动: 采样地址改走 PI 相位表, 默认非理想 PI
--------------------------------------------------------------------------------
1. runner 新增 PiNonideal 选项('ideal'|'ab_constant'), 默认 'ab_constant', 并传给
   cdr_top; 此前 runner 把 cfg.PiNonideal 硬写成 'ideal'。cdr_pi 的 a+b=1/atan2
   相位表模型与 cdr_top 的 PiNonideal 校验都是既有代码, 本次未改。
2. 只加选项是不够的: 原来块起始地址用的是原始 CodeWrapped, 它隐含"code 到相位完全
   线性"的假设, 于是 cdr_pi 算出的非理想相位表会被算完即丢。现在 UI 内采样偏移取自
   相位表本身: sampleOffset = round(top.PhaseInterpolator.getLocalIndex())。
   在 PiNonideal='ideal' 下该表恰为恒等表, 此式等于 CodeWrapped, 改动逐比特 no-op;
   保留 'ideal' 正是为了旧行为可复现、可做 A/B。
3. 定量(PiNumBit=7, 128 sample/UI, 1 LSB = 1 code = 1 个波形样点):
   ab_constant 相位表 INL = ±1.445352 LSB = 2.890703 LSB pk-pk, RMS 1.037876 LSB。
   缓存按整数样点寻址故偏移被 round, INL 量化到 ±0.5 LSB; 存活的扰动是
   round(localIndex)-code ∈ {-1,0,+1}, 覆盖 52/24/52 个 code, 即**128 个 code 里有
   104 个的采样点相对旧的理想 PI 地址移动了一整个样点(1/128 UI)**。同一个 round 会
   把 0.7 LSB pk-pk 以下的 INL 抹平: 这是本 harness 整数寻址的限制, 不是 cdr_pi 的。
4. 已否决(用户确认): 不做 PiInlPkPkLsb 幅度缩放旋钮, 原生 2.891 LSB pk-pk 即物理模型。
5. 五张收敛图新增两级降档标记(stage-1 绿/带 SNR 阈值, stage-2 紫), 均 NaN-safe。
   stage-2 标签写**armed 的门控名**(gate: freq-state|center-touch)而非 "lock":
   只有 freq-state 门是锁定判据的分量, center-touch 是独立码域判据。
6. 新增 result 字段: PiNonideal / FfeGateCriterion / Stage1SettleBlock /
   Stage2GateBlock / AdcBlockUi / CdrFfePreTapCount。两个 block 字段取自 monitor
   自身闩锁而非离线反推, 不可能与当次真正armed的判据不一致。

  +100 ppm ideal      : 8/8 all=1 util=0.8192 slewSat=0 |Pending| 0.1220..0.1985
  +100 ppm ab_constant: 8/8 all=1 util=0.8192 slewSat=0 |Pending| 0.3560..0.4060
  +110 ppm ideal      : 8/8 all=1 util=0.9011 slewSat=0 |Pending| 0.3380..0.4530
  +110 ppm ab_constant: 0/8 all=0 util=0.9011 slewSat=8/8 |Pending| 0.7715..1.0240
两条实测结论:
  (a) "+100 ppm 非理想" 的 pending 背压与 "+110 ppm 理想" 基本同量级, 即非理想相位表
      按这个先兆量算大约吃掉 10 ppm 的正向余量;
  (b) 正向全相位上限是**依赖 PI 的**: +110 ppm 的能力只在理想 PI 下成立; 用默认的非
      理想 PI 时 8 个相位全部触发 SlewSatPendingTol=0.5 守卫并被正确拒绝锁定。
注意两个 +110 ppm 臂的 mean|DeltaCode| 都是 0.9005..0.9015, 说明失效**不是**平均意义
上撞到 MaxDeltaCode=1 天花板, 而是 slew 背压积压 —— 这正是 pending 守卫存在的意义。
结论: ±100 ppm 的要求在非理想 PI 下达标, 但正向余量已不足 10 ppm。

--------------------------------------------------------------------------------
十二、限制与遗留
--------------------------------------------------------------------------------
- INL 被整数寻址量化成 {-1,0,+1} 三级台阶, 亚 LSB INL 无法表示。
- +110 ppm 那几行只有 8 相位, 是余量测量, 不能当作全相位结论。
- 未在非理想 PI 下重新探负方向边界(只确认 -100 ppm 达标, 见 _m100 目录)。
- 上文第七节"本目录 Stage2Block 全为 n/a"只适用于旧产物; 本次 32/32 触发。
- ppm_lock_summary.txt 原先称 freq-state 的 Stage2Block 与 LockBlock "by
  construction" 相等, 说法过强: 非零 ppm 判据是合取, 还要求
  detectRotationPeriodLock, 正确的结构性结论只能是 Stage2Block <= LockBlock。该文件
  已改为此表述并打印实测一致性(本工况 32/32 行精确相等, 0 行更早)。

--------------------------------------------------------------------------------
十三、复现方法
--------------------------------------------------------------------------------
从套件目录:
    setup_cdr_three_loop_wi_ppm_paths('all');
    r = cdr_three_loop_ppm('FreqOffsetPpm', 100, 'StartPhaseStep', 4);
    make_ppm_stage_eyes('ResultDirs', {'cdr_three_loop_ppm_p100'});
恢复旧的理想 PI 行为(逐比特等价于本次改动之前):
    cdr_three_loop_ppm('FreqOffsetPpm', 100, 'StartPhaseStep', 4, ...
        'PiNonideal', 'ideal');
余量探测复现:
    cdr_three_loop_ppm('FreqOffsetPpm', 110, 'StartPhaseStep', 16, ...
        'SaveOutputs', false);
快速 smoke:
    cdr_three_loop_ppm('FreqOffsetPpm', 100, 'NumBlock', 4000, ...
        'StartPhaseList', [16 64], 'SaveOutputs', false);
注意 StartPhaseStep 默认 16(只 8 个相位), 本套件历史上的"全相位"指 32 相位, 必须显式
传 4。重跑同一条命令可复现相同汇总数值(确定性)。
