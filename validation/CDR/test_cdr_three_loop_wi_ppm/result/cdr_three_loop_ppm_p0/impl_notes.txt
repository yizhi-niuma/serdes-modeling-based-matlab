--------------------------------------------------------------------------------
一、本工况的作用
--------------------------------------------------------------------------------
0 ppm 是零频偏基线, 在本套件中承担两个职责:
  1) 基线: 确认三环(SS-MMPD 相位环 / dLev 电平环 / CDR-FFE 系数环)在无频偏下能从
     全部初始相位收敛到同一采样相位, 即 v4 套件原本验证的能力;
  2) 回归哨兵: 换挡策略是三个工况共用的。0 ppm 对"降档是否发生"最敏感 —— 降档负责
     压低稳态梯度噪声并收紧锁定相位, 如果为了让 -100 ppm 通过而把降档推迟到几乎
     不触发, 0 ppm 的锁定相位一致性就会退化。因此 0 ppm 与 ±100 ppm 必须同时通过,
     单独调通任一侧都不算完成。

该约束是实测出来的, 不是假设: 把第一级降档判据收紧到 DlevSettleWindow/Tol =
128/0.1 或 200/0.05 时, ±100 ppm 可达 32/32 AllPhaseLock=1, 但 0 ppm 的锁定相位
离散度从 4 码恶化到 13~15 码 (判据上限 captureBandHalfWidth=6) => AllPhaseLock=0。
改用固定块触发(fire@2001)在 8 起始相位下看似三者皆过, 扩到 32 起始相位后 -100 ppm
退化为 31/32 => 说明所需降档时刻随起始相位与 ppm 变化, 固定阈值/固定块号都不成立。

--------------------------------------------------------------------------------
二、关键实现要点 (与 ±100 ppm 共用)
--------------------------------------------------------------------------------
两级降档:
  第一级 capture -> settle , 门控 = 判决导向 SNR 的 EWMA
      FOM = 10*log10(mean(decision^2)/mean(sliceError^2)) , 逐 block
      cdr_top.blockSnrDb 算 FOM , loop_monitor.updateSnrSettle 做判决(只判决不施加)
      SettleGate='snr' , 阈值 15 dB , alpha=1/128 , minBlock=200
      触发后 dLev 0.5 -> 0.1 , FFE 0.001 -> 2e-4
  第二级 settle -> PVT tracking , 门控 = 既有相位带锁定门控 loop_monitor.updateFfeGate
      触发后 FFE -> FfeStepSizePvtTrack=2e-4 , dLev -> DlevStepSizePvtTrack=0.02

capture 期 FfeStepSize 取 0.001（库默认 0.004 的 1/4）；
FfeAdaptEnableMask=[1 1 0 1 1 1]
冻结主抽头, 环路只能靠前后抽头整形脉冲, 这会移动有效游标从而移动 MMPD 零点, 不同
起始相位因此收敛到不同锁定相位。走位量与步长成正比, 0 ppm 侧实测锁定相位离散度:
    FfeStepSize  0.001  0.002  0.004  0.008
    离散度(code)     3      6     12     21
0 ppm 正是这一项的最敏感工况 —— 库默认 0.004 在此已超判据(12 > 6)。

--------------------------------------------------------------------------------

纯默认无参配置, FreqOffsetPpm=0:

  SnrSettleMinBlock=200 , FfeStepSize=0.001 , FfeStepSizeSettle=2e-4 ,
  FfeStepSizePvtTrack=2e-4 , StepSize=0.5 , StepSizeSettle=0.1 ,

--------------------------------------------------------------------------------
四、关键结果与结论
--------------------------------------------------------------------------------
- 32/32 起始相位锁定, AllPhaseLock=1。
- commonLockPhase=113 , 锁定相位离散度 3 码。
- 频率判据不适用: 0 ppm 下理论频率态为 0, 旋转周期判据亦不适用(rotationApplicable
  =false), 故 FreqLockFlag 全 0 且 FreqLockDiagnostics.MeanValue 为 NaN 属预期,
  该工况的锁定判定由相位带驻留判据(events/band)给出, 不参与频域判据。
- 同配置下 -100 ppm 与 +100 ppm 亦为 32/32 AllPhaseLock=1 (离散度 3 / 2 码,
  freqStateMean +0.8193 / -0.8192, 理论 ±0.8192)。三工况同时达成全相位捕获。

六、三眼窗口、结果、限制与复现
--------------------------------------------------------------------------------
make_ppm_stage_eyes.m 先从保存的 SnrDbTrace 精确重放
loop_monitor.updateSnrSettle 的 EWMA，再用与运行 pass/fail 完全相同的锁定检测器和容差
逐个前缀 1:k 重放首次锁定。三个 2048-UI 窗口依次为：
  1) 第一级 SNR mu 降档后：从 block 961 开始；这是 block>=200 后 EWMA(alpha=1/128)
     首次达到 15 dB 的位置。
  2) 锁定判据首次满足后：从 block 2732 开始；0 ppm 使用
     detect_pi_center_touch_lock，频率态单项判据不适用。
  3) final：运行最后 2048 UI。
LockWindowBlocks=2000，忠实的滑窗判定在 block 2000 前没有完整窗口，因此第二行锚点
下限为 2000；它表示“末尾 2000-block 窗口首次满足判据的块”，不是环路锁定的瞬时刻。
CaptureBlock=768 只保留作上下文，不再作为眼图锚点。

helpers/build_ppm_eye_set.m 接受 N 个锚点并追加一个尾窗，按
    absSample0(k) = (BaseUi + (k-1)*AdcBlockUi + UiSlipTrace(k)) * ...
        SamplesPerUi + PhaseCodeTrace(k) + DriftSampleTrace(k)
重建地址；0 ppm 时 DriftSampleTrace 为零，自然退化为无漂移地址。helper 逐块精确核对
sub-UI code 与 EyePhaseUnwrappedTrace。每个锚点窗口使用该锚点块自己的 FFE 系数快照，
final 使用末块快照；它们都是整窗固定抽头的离线视图，不是运行期逐块变化抽头的重放。
ADC、固定抽头 FFE 和 2-UI 密度仍委托同级 build_cdr_ffe_eye。
helpers/plot_ppm_eye_set.m 输出三个独立图，并另画一个刻意设为 1500x1500 的三行比较图。
marker 由未包裹的 tracked-eye phase 先统计、再包裹到一 UI；span 因而可跨越 0/128
边界。相邻 2-UI 密度列彼此重叠，不能视为独立样本。

八、本次改动与本工况的作用
--------------------------------------------------------------------------------
1. runner 新增 PiNonideal('ideal'|'ab_constant', 默认 'ab_constant'), 并把 UI 内采样
   偏移从原始 CodeWrapped 改为取自 PI 相位表:
       sampleOffset = round(top.PhaseInterpolator.getLocalIndex())
   在 'ideal' 下相位表恰为恒等表, 该式等于 CodeWrapped, 改动逐比特 no-op。
   定量(7 bit PI, 128 sample/UI, 1 LSB = 1 code = 1 样点): ab_constant 的 INL =
   ±1.445352 LSB = 2.890703 LSB pk-pk (RMS 1.037876); 整数寻址把它量化成
   round(localIndex)-code ∈ {-1,0,+1}, 覆盖 52/24/52 个 code, 即 128 个 code 中有 104
   个采样点移动了一整个样点(1/128 UI)。0.7 LSB pk-pk 以下的 INL 会被该 round 抹平。
2. 本工况是**降档与游标走位的哨兵**, 必须与 ±100 ppm 同批跑: 它是唯一仍使用
   center-touch 第二级门控的工况(FfeGateCriterion='auto' 只在恰好 0 ppm 时解析为
   center-touch), 也是判断锁定相位离散度是否由 capture 期 FFE 步长引起的对照点。
3. 五张收敛图新增两级降档标记; stage-2 标签写**armed 的门控名**(本工况为
   "gate: center-touch")而不是 "lock"。这一点在本目录尤其重要: center-touch 与锁定
   判据无关, 把它标成 lock 在 0 ppm 图上是明确错误的。

--------------------------------------------------------------------------------
十一、限制与遗留
--------------------------------------------------------------------------------
- INL 被整数寻址量化成 {-1,0,+1} 三级台阶, 亚 LSB INL 在本 harness 中无法表示。
- 本工况第二级门控仍是 center-touch, 29/32 触发是它的真实能力。**用户确认(2026-09-26):
  0 ppm 下 stage-2 未触发可以接受, 环路本身是收敛的, 不需要改判据或改默认。**
  依据: 在当前默认步长下 stage-2 只改 dLev 步长(dLev 0.1->0.02; FFE 的 settle 与
  pvt-track 同为 2e-4, 第二级对 FFE 无影响)。因此那 3 个未闩锁相位的唯一后果是尾段
  dLev 停在 mu=0.1 而非 0.02, 即 dLev 稳态失调略大, 不影响锁定判据、相位环与 FFE;
  实测这 3 个相位同样计入 Locked=32/32, 且本工况锁定相位离散度 2 码是三个工况中最小。
  如仍希望 0 ppm 也 32/32 触发, 可显式传 'FfeGateCriterion','freq-state'; 本次刻意
  不改默认, 以保持 0 ppm 与历史产物的可比性。
- 上文第七节"本目录结果是旧门控产物"只适用于旧产物。
