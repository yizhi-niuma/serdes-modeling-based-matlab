## 1. 记法约定

本文件统一用 **MATLAB 原生三元组 `(signed, WordLength, FractionLength)`**，
不用 `sQm.n`。理由：无歧义，且它就是 `numerictype` 的实参，文档与代码同一套数。

```matlab
T = numerictype(1, 18, 16);   % signed, 总位宽 18, 小数位 16
                              % → 整数位 = 18 - 1 - 16 = 1, 范围 ±2, LSB = 2^-16
```

- `WordLength` 是**总位宽**，含符号位。
- 整数位 = `WordLength - signed - FractionLength`。
- 范围 = `±2^整数位`；LSB = `2^-FractionLength`。
- RTL 对应 `logic signed [WordLength-1:0]`，**小数点在 Verilog 里不存在**，
  纯靠本文件约定。这就是本文件必须存在的原因。

## 2. 字长怎么定的（方法，不是结论）

两类位宽依据完全不同，必须分开定：

| | 依据 | 数据来源 |
|---|---|---|
| **整数位** | 动态范围 `ceil(log2(absmax)) + 1` | 普查的 min/max，+1 bit 瞬态余量 |
| **小数位** | **最小有效增量**，与范围无关 | 普查的逐块 \|diff\| 的 1% 分位，+3 bit 余量 |

第二条是整个普查存在的理由：对 FFE 系数、dLev 这类自适应量，
**若 LSB 粗于单块更新量，累加器直接进死区停摆** —— 波形上看着像收敛，实则冻住。
这种失效极难事后定位，只能靠事先按增量定字长来避免。

**通用结构**：自适应量一律 **宽累加器 + 窄输出**。
累加器按最小增量定小数位，送乘法器/比较器的那一份按物理分辨率截断。
两者是两个不同的 Q 格式，必须分别记录。

## 3. 两项待决策（开工前必须解掉）

### 3.1 `FrequencyState` 的整数位：按钳位值还是按实测？

| 口径 | 整数位 | 格式 | 风险 |
|---|---|---|---|
| 按实测 −0.928 ~ +0.838 | 1 | `(1, 17, 15)` | **取样偏差**：三组工况全部锁定成功，积分器从未撞到 ±4 钳位。失败/饱和场景不在数据里 |
| 按 `FrequencyLimit = 4` | 3 | `(1, 19, 15)` | 多 2 bit，但覆盖所有可能状态 |

**我的建议：按钳位值，`(1, 19, 15)`。** 理由：

1. `cdr_loop` 的积分器**本来就会被钳到 ±FrequencyLimit**（`setFrequencyLimits` 显式做饱和），
   所以 ±4 是这个寄存器的**定义域**，不是"碰巧没到过"。
2. 定点模型的职责之一就是复现失败场景（railed 频率态是 `loop_monitor`
   饱和守卫的判别对象）。如果字长按成功运行定，失败场景会溢出回绕，
   守卫读到的值将是错的，**守卫本身就失效了**。
3. 代价只有 2 bit。

> ⚠️ 待你确认。确认前所有依赖它的下游格式按 `(1, 19, 15)` 预留。

### 3.2 `PendingCode` 的钳位值

浮点模型里它**无界增长**；RTL 必须钳。但 `loop_monitor` 的 slew 饱和守卫
**正是读它**（`mean|PendingCode| >= SlewSatPendingTol`，默认 0.5）。

实测对照：

| 场景 | `mean\|PendingCode\|` | 峰值 |
|---|---|---|
| 本次三工况（全部锁定） | — | **−66 ~ +5** |
| +100 ppm（历史） | 0.13 | — |
| +110 ppm | 0.44 | — |
| +120 ppm | 7~9 | — |
| +130 ppm（slew 饱和） | **5408 ~ 7883** | — |

**矛盾点**：钳得太紧，守卫永远读不到大值，饱和检测失效；钳得太松，寄存器白费。

**我的建议：钳位 ±1024，格式 `(1, 12, 0)`。** 理由：

- 守卫阈值是 **0.5**（均值），钳位 1024 比它大三个数量级，不可能影响判决。
- +130 ppm 的 5408~7883 会被钳到 1024，但那时 `mean|PendingCode|` 仍远超 0.5，
  **守卫照常触发**，饱和判别不受影响。
- 比"按实测 ±66 定"安全得多：±66 恰好落在 +120 ppm 的 7~9 和 +130 ppm 的 5408
  之间，真跑边界 ppm 会溢出。

> ⚠️ 待你确认。确认后需要**重新标定** `SlewSatPendingTol`，
> 并在 ±100/±110/±120/±130 ppm 上复测守卫是否仍正确区分。

## 5. 必须改结构的四处（不只是换类型）

### 5.1 slicer 与 dLev 必须用**同一个截断值**

`dlev_loop.sliceErrors` 用**精确相等**判归属（`dlev_loop.m:170-171`）：

```matlab
isInner = abs(d) == obj.DLevInner;
isOuter = abs(d) == obj.DLevOuter;
```

定点下 dLev 存的是宽累加器 `(1,23,16)`，而 slicer 判决用的是截断后的
`(1,9,2)`。**如果比较时一边用累加器、一边用截断值，这个 `==` 永远不成立**
→ 内外环归属全错 → `innerErr`/`outerErr` 恒零 → dLev 环静默死掉，
而且波形上完全看不出来。

**契约**：slicer 判决、`d` 的取值、`==` 比较三者**必须用同一个 `(1,9,2)` 截断值**。
累加器只在更新时参与，绝不进入比较。

### 5.2 voter 的除法折进增益

`cdr_voter` 的 `mean` 模式做 `sum/denominator`，且默认 `'auto'` 取 `numel(phaseDecision)`
—— **块长相关的除数在 RTL 里不可实现**。

等价变换（数学上严格等价，省一个除法器）：

```
phaseError = sum(phaseDecision)        % 不除，整数，范围 ±64
Kp: 8.0  → 8.0/64  = 0.125
Ki: 0.03 → 0.03/64 = 4.6875e-4
```

实测佐证：`phaseError` 浮点实测 −0.219 .. +0.188，乘回 64 得 −14 .. +12，
与 `EdgeCountPerBlock`（0 .. 22）同量级 ✓

**⚠️ `EdgeCountPerBlock` 最小值是 0** —— 存在零事件的块。定点实现必须
**显式处理"本块无更新"**，不能依赖除法的自然行为（浮点版把这个边界藏起来了）。

### 5.3 `fix()` 不是算术右移 —— 本设计最危险的一处

`cdr_loop.updateFast` 用的是 **`fix()`（向零取整）**：

```matlab
rawDeltaCode = fix(residueAccum);
```

而算术右移 `>>` 是 **`floor`（向负无穷）**。对负数**结果不同**：

| 输入 | `fix` | `floor`/`>>` |
|---|---|---|
| +1.7 | +1 | +1 |
| **−1.7** | **−1** | **−2** |

直接写 `bitsra` 会在零点附近引入**方向不对称的偏置**。

**而这个项目已经存在一个负 ppm 方向的捕获不对称**（冷启动盲区，负向上限
−30 ppm vs 正向 +110 ppm）。一旦混进 floor/fix 错误，**几乎必然被误诊成物理现象**。

**契约**：`cdr_fx` 必须实现显式的 `fixToZero(x, shift)`，不得用裸 `bitsra`。
作为对照，`cdr_pi.m:115` 用的**本来就是 `floor`**，那里可以放心直接移位 ——
**同一个仓库里两种取整语义并存，必须逐处核对，不能一把梭。**

### 5.4 `sign(0) = 0` 的三值语义必须保留

MATLAB `sign` 是三值的（−1/0/+1），RTL 符号位是两值的。

SS-LMS 依赖这一点：`sliceErrors` 把环外样本置零后，`sign(0) = 0`
**正是"环外样本不贡献"的实现机制**。换成两值符号位，环外样本会开始贡献，
内外环解耦被破坏。

**契约**：定点 `sign` 必须显式返回三值。

## 6. `loop_monitor` 算硅的四个后果

| # | 改动 | 是否等价 |
|---|---|---|
| 1 | dB 判据 → 比值比较：`10*log10(Pd/Pe) >= 15` ⟺ `Pd >= 31.6*Pe` | ✅ **判决完全等价**，`Inf`/`NaN` 分支同时消失 |
| 2 | 窗口 2000 → **2048** | ❌ **会改变判据数值**，尾窗长 2.4% |
| 3 | 2048 深缓冲 → 流式累加器（`sum` + `sumOfSquares`） | ❌ 数值路径不同，需重新验证 |
| 4 | `PeriodCov = PeriodStd / PeriodMean` → 交叉相乘 `Std*100 <= Mean*Tol` | ✅ 等价，消除除法器 |

**合并后果**：②③④ 都会让判据结果发生变化。
**`loop_monitor` 是唯一一个不能沿用现成验收阈值、必须重新标定的块。**

这也是实施顺序把它排在**最后**的原因：前三步都能用现成的
`32/32 + freqMean ±0.8192` 判据当锚，到它这里锚本身要重钉。

## 7. 实施顺序

按「出错可归因」排，不按重要性。每步只定点化一个块，其余保持浮点，
任何偏离都能唯一归因：

| 步 | 内容 | 验收口径 |
|---|---|---|
| 1 | `cdr_voter` + `cdr_loop` + `cdr_pi` 时序链 | **容差内等价**（本步含 §5.2 增益重标定，需重建基线） |
| 2 | `dlev_loop`（2 个累加器，最简单） | 判决级位精确 |
| 3 | `cdr_ffe` + `cdr_ffe_loop`（乘法密集，字长真正吃紧） | 判决级位精确 |
| 4 | `loop_monitor` 判据改写 | **重新标定**，见 §6 |

**不要先做 FFE** —— 它扰动下游一切，第一个做会让后面每步都没有干净基线。

## 8. 验收

**两档**：

| 档 | 内容 | 为什么可达 |
|---|---|---|
| **判决级位精确** | `PhaseDecision` / `DataSymbol` / `ErrorBit` 必须完全一致 | 这三个**本来就是数字量**，比任何眼图指标都强 |
| 轨迹级容差 | `FrequencyState` / dLev / FFE 系数在声明容差内 | 量化噪声不可避免 |

**回归矩阵直接复用现成的**，不要发明新判据：

```
−100 / 0 / +100 ppm × 32 相位
判据：32/32 locked、AllPhaseLock=1、freqMean ∓0.8192、spread ≤ 3
```

这些阈值是花大代价标定出来的，**定点化不是重新标定它们的时机**。

额外加一个一等公民输出：**逐节点溢出/饱和计数**，不要只有 pass/fail。
